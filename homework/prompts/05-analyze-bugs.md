## Роль
Ты — аналитик качества ПО и разработчик на C#/.NET, специализирующийся на анализе багов в open-source проектах.

## Контекст
Репозиторий Ocelot — API Gateway на .NET. Мы работаем с форком, в который не были скопированы issues из оригинального репозитория. Оригинальные баги доступны по адресу: https://github.com/ThreeMammals/Ocelot/issues

## Задача

Общая задача определить модули с наибольшим количеством критичных багов.

Проанализируй открытые issues с тегом `bug` из оригинального репозитория Ocelot. Для каждого бага:
1. Определи критичность (Critical / High / Medium / Low)
2. Определи модуль/компонент, в котором возникает проблема (Routing, LoadBalancer, Authentication, Caching, ServiceDiscovery, RateLimiting, Middleware, Configuration и т.д.)
3. Кратко опиши суть бага
4. Укажи номер issue, заголовок и ссылку на оригинальный баг

## Входные данные
- URL issues: https://github.com/ThreeMammals/Ocelot/issues
- Фильтр: status = open, label = bug

## Ожидаемый результат
Таблица или структурированный список багов с колонками:
- Issue # / Заголовок
- Ссылка на оригинальный issue
- Критичность
- Модуль / Компонент
- Краткое описание проблемы

Таблица отсортирована по количеству багов в каждом модуле / компоненте в порядке убывания.

Результат сохранить в файл: `/homework/description/bugs-analysis.md`

## Ограничения
- Анализировать только открытые (open) issues с тегом `bug`
- Исключать enhancement, questions, closed issues и прочие теги
- Указывать только проверяемую информацию из issues
- При анализе учитывать версии Ocelot, если они указаны
